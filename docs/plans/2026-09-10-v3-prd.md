# Herdr Studio V3 — PRD 与验收标准

日期：2026-09-10 · 基线：`v2` 标签 · 流程：TDD（本文档的 Playwright 契约先行）

V2 遗留反馈：① 工作区与标签两栏割裂；② 对话视图本质仍是 TUI 文本 + 卡片，不是
ZCode/Codex Desktop 那种应用原生渲染的沉浸式对话；③ 统一模式拖拽卡顿明显，且
输入目标不明确。V3 三项功能逐一解决。

---

## F1 工作区与标签合并

**描述**：取消独立标签列（`.tabcol` 整列移除，主区获得全部宽度）。左侧栏改为
合并树：工作区行（`.ws-item` 保留）右侧加展开箭头 `[data-testid="ws-expand"]`，
展开后子行显示该工作区的标签（复用 `.tab-item` 类名，缩进层级），点击子行 =
选中该工作区+标签。当前激活工作区自动展开，其余折叠；仅一个工作区时可默认展开。
主区头部保留标签名标题。

**兼容**：`.ws-item` / `.tab-item` / `.tab-item.active` 类名必须保留（V1 CDP e2e
依赖）；V1 用例若因折叠交互失败，允许最小修改并在报告中列出。

**验收**：
- `[data-testid="ws-expand"]` 点击切换展开/折叠（aria-expanded 翻转）
- 展开后 `.tab-item` 出现在该工作区行下方；点击子行后 `activeTabId` 切换且该行高亮
- 页面中不存在 `.tabcol` 列

## F2 沉浸式对话流（核心重做）

**描述**：对话视图从「卡片包着 TUI 文本」升级为**应用原生渲染的全沉浸对话面**：
主区即为对话表面（无 reader-card 包裹、无 TUI 文本块背景），视觉效果对齐
ZCode / Codex Desktop：

- **assistant 正文按 Markdown 渲染**（复用 marked）：粗体/斜体/列表/链接/行内代码
  真实生效，代码块带语法高亮着色（允许新增 `highlight.js` 依赖，或自写轻量着色）
- **工具行渲染为带彩色标签的行内条目**：`[data-testid="tool-chip"]` 显示工具名
  （彩色徽标，按工具名 hash 取主题色），摘要文字随行，点击展开详情
- **图片内联**：正文/工具行中出现的图片文件路径（.png/.jpg/.jpeg/.gif/.webp/.svg，
  且 fs:read 可读）渲染为内联图片 `[data-testid="chat-image"]`（走既有 fs:read
  data URL 通道），路径本身不再显示为裸文本
- **流式**：轮询更新到达时仅重渲染变化的尾部块（块级 React.memo + 稳定 key），
  滚动贴底跟随，无整屏闪烁
- **用户消息**：右对齐轻量气泡（保留），meta（Worked for）渲染为居中时间戳分隔线

**技术**：`chat-parser` 增加块级字段（assistant 的 md 源、tool 的名称+摘要、
image 路径抽取）；渲染层新组件流式渲染。**V2 的 msg-* testid 契约保留**
（msg-user/msg-tool/msg-assistant/msg-code），新增 chat-immersive / tool-chip /
chat-image。`view-raw` 兜底不变。TUI 装饰行仍不得出现。

**验收**：见 `tests/playwright/v3-features.spec.mjs` F2 组（markdown strong 生效、
tool-chip 存在、图片路径→内联 img、流式更新 ≤2.5s、无 reader-card 包裹）。

## F3 统一模式：性能 + 输入目标 + 选中高亮

**描述**：
1. **性能**：消除拖拽与流式更新的卡顿。要求（评审逐条核对）：
   - cell 组件 `React.memo`，按 `paneId + revision` 订阅各自输出，禁止 Mosaic 整体
     因单 cell 文本变化重渲染
   - ANSI→HTML 解析结果按文本缓存（Map<paneId, {text, html}>），文本不变不重解析
   - `pane.layout` 轮询取消 1s 盲轮询：仅在 拖拽中/拖拽结束/herdr `layout.updated`
     事件/快照刷新 时拉取
   - 拖拽期间用本地预览位置即时反馈（transform），松手才提交 `pane.resize`
2. **输入目标**：统一模式底部输入框新增 `[data-testid="input-target"]` 下拉，列出
   当前 tab 全部 pane（agent 显示名 / shell N）；发送目标 = 下拉选中项。分屏模式
   不显示该下拉（行为同 V2）。
3. **选中高亮**：点击马赛克 cell 即选中为输入目标：cell 加
   `[data-selected="true"]` 与明显高亮环（`mosaic-pane-selected`，accent 描边 +
   微光）；下拉与点击双向同步；默认选中聚焦 pane。

**验收**：见 `tests/playwright/v3-features.spec.mjs` F3 组（下拉存在且含全部 pane、
选目标后 echo 落在目标 pane、点击 cell 高亮并同步下拉、拖拽仍工作、cell 更新延迟
≤2.5s）。

## 工程约束（评审依据）

1. V1 + V2 全部测试保持通过：`npx playwright test`（v2 spec 13 例 + v3 spec）与
   `node tests/run-all.mjs`。V1 e2e 选择器允许最小修补（合并侧栏交互），逐条列出。
2. 新增运行时依赖仅允许 `highlight.js`（若实现语法着色选择引库）。
3. msg-* testid 与 `.reader-card` / `.ansi`（raw 视图）/ `.ws-item` / `.tab-item`
   / `.pane-chip` / `.composer textarea` 兼容性保留。
4. 性能三要求（memo/缓存/按需拉取）为硬性评审项，实现需在代码中可辨识。
5. `npm run typecheck` 通过；安全基线不变（fs 白名单、marked 转义、导航防护不得回退）。
