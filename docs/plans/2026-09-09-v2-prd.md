## F1 日夜模式切换

**描述**：标题栏新增主题切换按钮。夜模式 = 现有 Claude Code 风格（暖炭黑 #262624 / 赤陶橙）；
日模式 = ChatGPT Desktop 风格（白底 #ffffff、浅灰侧栏 #f9f9f9、近黑正文 #0d0d0d、
浅灰描边、无重阴影）。品牌强调色两种主题下均保持赤陶橙 #d97757。

**技术**：全部颜色已收敛为 `:root` CSS 变量（src/styles/global.css），新增
`html[data-theme="light"]` 令牌组覆盖；切换按钮写 `<html data-theme>` + localStorage
`herdr-studio-theme`，启动时恢复，默认 dark。所有组件样式必须只引用变量，禁止硬编码色值
（评审项）。

**验收 / 测试契约**：
- `[data-testid="theme-toggle"]` 点击后 `<html data-theme>` 在 dark ↔ light 间翻转
- 刷新后保持；首次启动默认 dark
- 令牌完整性：light 模式下 reader 卡片、侧栏、输入框无深色残留（人工 + 评审）

## F2 右侧功能栏（仿 ChatGPT Desktop）

**描述**：标题栏新增右侧栏开关。侧栏三块：
1. **工程文件树**：根目录 = 当前激活 pane 的 `cwd`（来自 herdr snapshot）；目录可展开，
   默认深度 3，跳过 `node_modules`/`.git`/隐藏目录；点击文件在下方预览。
2. **预览区**：`.md` 渲染为 HTML（新增依赖 `marked`）；图片（png/jpg/gif/svg/webp）
   直接显示；文本/代码等宽 `<pre>` 显示；其余类型显示「在默认浏览器打开」按钮
   （`shell.openPath`）。
3. 文件树支持在**当前工作区各 tab 的 cwd 之间快速切换**（顶部下拉，列出 snapshot 中
   去重后的 cwd 列表）。

**技术**：主进程新增 IPC：`fs:tree(dir, depth)`、`fs:read(path)`（返回
`{kind: "text"|"image"|"other", data}`，图片走 base64 data URL）、`fs:open(path)`。
本地工具，路径不做沙箱限制，但渲染层仅展示树内文件。marked 输出包含本地文件内容，
渲染前必须转义原始 HTML（`marked` + 转义或 `sanitize` 选项，评审项）。

**验收 / 测试契约**：
- `[data-testid="right-sidebar-toggle"]` 开关 `[data-testid="right-sidebar"]`
- `[data-testid="cwd-select"]` 下拉：至少包含种子工作目录
- `[data-testid="file-tree"]` 内 `[data-testid="file-item"]` 能看到种子目录的
  `sample.md` / `sample.png` / `sample.xyz`
- 点击 `sample.md` → `[data-testid="file-preview"]` 出现渲染后的标题元素
- 点击 `sample.png` → 预览区出现 `img`
- 点击 `sample.xyz` → `[data-testid="open-external"]` 按钮出现（测试不点击）

## F3 终端区双模式：分屏 / 统一

**描述**：主区顶部新增布局模式分段控件，与内容视图（F4）正交：
- **分屏模式（默认，与 V1 一致）**：顶部 pane 芯片切换，一次只显示一个 pane。
- **统一模式**：当前 tab 的所有 pane 按 herdr 真实布局拼成马赛克（数据来自
  `pane.layout` 快照的 rect，绝对定位百分比渲染），每个 cell 独立滚动（即"分页"）；
  cell 间出现可拖拽分隔条，拖动调用 `pane.resize {direction, amount}` 让 herdr 调整
  真实 TUI 布局，随后重新拉取 layout 快照刷新（即"鼠标调整大小"）。

**技术**：store 增加 `layoutMode: "separate" | "unified"`（localStorage 持久化，
默认 separate）。统一模式为激活 tab 建立 `pane.layout` 轮询（1s）+ 复用输出轮询改为
覆盖该 tab 全部 pane。cell 内容默认 raw ANSI 渲染（统一模式下也可切 F4 对话视图，
范围本 PRD 不强制）。

**验收 / 测试契约**：
- `[data-testid="layout-mode"]` 内 `layout-separate` / `layout-unified` 两个按钮，
  默认 separate
- 点击 unified 后出现 `[data-testid="mosaic"]`，cell 数 = 当前 tab pane 数
  （`[data-testid^="mosaic-pane-"]`），且各 cell 文本包含各自 pane 预先 echo 的标记
- `[data-testid^="splitter-"]` 存在；模拟拖动后至少一个 cell 的包围盒尺寸发生变化
- 切回 separate 恢复 V1 视图

## F4 对话视图（核心）：TUI → agent 对话流

**描述**：pane 内容视图从「直接倾倒 TUI 文本」升级为三档：
**对话（默认，agent pane）** / **原始输出** / **终端·V2（占位）**。对话视图把
`recent_unwrapped` 文本解析为结构化对话流，样式对齐 ZCode Desktop / ChatGPT Desktop：
用户消息右侧浅色气泡、assistant 正文左对齐排版文本、工具调用为可折叠等宽卡片、
代码块等宽底色块、TUI 装饰（边框、提示符框、状态行）不再出现。

**解析器**（新模块 `src/chat-parser.ts`，纯函数 `parseTranscript(text: string): Block[]`，
无 React 依赖，规则通用、按 marker 启发式，不绑定特定 agent）：
1. 先剥离 ANSI（复用 anser 反解或自写 strip）；
2. 丢弃 TUI 装饰：仅由 `─`/`━`/`─…` 构成的分隔行、`Worked for …` 状态行、
   末尾提示符框（`› …` / `❯ …` 空提示）、空行连续折叠；
3. 块分类：`❯ ` / `>` 前缀 → `user`；`⏺` / `●` / `• ` 前缀 → `tool`；
   ``` 围栏 → `code`；其余连续文本 → `assistant` 段落（保留换行）。
4. Block 类型：`{type: "user"|"assistant"|"tool"|"code"|"meta", text}`；meta 块渲染
   为弱化分隔（如 Worked for 保留为时间戳分隔）。

**已知限制（写入文档，不阻塞验收）**：真实 agent TUI 的富布局（弹层、差分视图、
表格）无法 100% 结构化，解析保真度按 marker 规则迭代；`view-raw` 永远可用作兜底。

**验收 / 测试契约**：
- agent pane 默认进入对话视图：`[data-testid="chat-thread"]` 存在
- 分段控件 `[data-testid="view-chat"]` / `[data-testid="view-raw"]` 可切换；
  raw 下 `.ansi` 原文可见
- 种子合成转写（shell pane echo 含 `❯ 用户消息` / `⏺ 工具行` / 普通正文）解析后，
  thread 内出现 `msg-user` / `msg-tool` / `msg-assistant` 块，且 TUI 装饰行
  （`─────`）不作为消息出现
- 非 agent（shell）pane 默认仍为原始输出视图（对话视图可手动开启）

## 工程约束（评审依据）

1. **V1 回归必须保持全绿**：`node tests/run-all.mjs`（协议层 + CDP E2E）不允许出现
   required 失败；因 UI 重构必须调整的 V1 选择器，需在实现 PR 中明确列出并说明。
2. 新增运行时依赖仅允许：`marked`。开发依赖新增：`@playwright/test`。
3. 架构沿用：主进程 IPC / zustand store / api.ts 类型封装 / CSS 变量令牌；
   禁止引入 UI 框架。
4. 所有新交互元素必须有 `data-testid`（契约见上），样式只引用主题变量。
5. TypeScript `npm run typecheck` 必须通过。

## 测试基建

- Playwright：`@playwright/test` + `_electron`（playwright-core 内置，无需下载浏览器，
  安装时 `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`）。
- 配置 `playwright.config.mjs`：testDir `tests/playwright`，workers=1，timeout 60s。
- 隔离策略与现有 e2e 相同：`tests/helpers/env.mjs` 的一次性会话 + 种子数据
  （cwd 指向项目目录并预置 `tests/fixtures/sample.md|png|xyz`）。
- 运行：`npx playwright test`；V1 回归：`node tests/run-all.mjs`。
